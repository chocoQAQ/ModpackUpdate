# 配置文件说明

本文对应 ModpackUpdate 0.3.0-preview.1，适用于 Fabric 1.20.1 / 1.21.1 与 NeoForge 21.1.266 / Minecraft 1.21.1。各构建使用相同配置字段，加载器类型由模组自动识别。整合包作者通过 `config.json` 设置更新地址和安装策略，客户端通过 `installed.json` 记录已安装版本及文件基线。

## 文件位置与生效时机

两个文件都位于当前游戏实例的根目录下。使用版本隔离的启动器时，应以该实例实际使用的游戏目录为准。

```text
<游戏根目录>/ModpackUpdate/config/config.json
<游戏根目录>/ModpackUpdate/config/installed.json
```

首次正常启动检查时，如果 `config.json` 缺失，程序会生成下方默认配置。配置在每次启动检查时读取，修改后于下次启动生效。文件使用 UTF-8 编码、JSON 对象和本文列出的字段名称，布尔值使用 `true`、`false`。

省略字段时采用程序默认值。未知字段会被忽略，字段拼写需要与文档一致。填写时使用标准 JSON，所有键和字符串使用双引号，并去掉注释和末尾多余的逗号。

## 默认配置

```json
{
  "enable": false,
  "update-service-url": "",
  "pack-id": "",
  "silent-update": false,
  "delete-replaced-mods": false,
  "timeout-seconds": 10,
  "protected-paths": [
    "options.txt",
    "optionsof.txt",
    "servers.dat",
    "saves/",
    "screenshots/"
  ]
}
```

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `enable` | 布尔值 | `false` | 启用启动时的版本检查 |
| `update-service-url` | 字符串 | `""` | 发布元数据 JSON 的 URL |
| `pack-id` | 字符串 | `""` | 当前整合包的固定标识，启用更新时需填写 |
| `silent-update` | 布尔值 | `false` | 自动接受新版本，按下文规则显示冲突选择和安装结果 |
| `delete-replaced-mods` | 布尔值 | `false` | 成功安装后清除本次被覆盖的旧模组备份 |
| `timeout-seconds` | 整数 | `10` | 网络连接与请求的超时秒数 |
| `protected-paths` | 字符串数组 | 上方五个路径 | 在安装计划中跳过的文件与目录 |

## 启用更新

作者可以使用下面的最小配置，其余字段采用默认值。示例域名需要替换成自己的更新地址。

```json
{
  "enable": true,
  "update-service-url": "https://updates.example.com/my-pack/latest.json",
  "pack-id": "my-pack"
}
```

`update-service-url` 指向发布元数据，其中包含版本、公告、索引 URL、overrides 信息和完整包 URL。地址格式与内容约定见发布协议。生产地址使用 HTTPS，本地调试支持 `http://localhost` 和 `http://127.0.0.1`，可以附带端口。URL 中的用户名、密码和 `#` 片段会被拒绝。 [发布协议](publishing-protocol.md)

`pack-id` 在配置、发布元数据和已有安装记录中应保持一致。客户端对该标识进行区分大小写的匹配，版本升级期间保持同一标识。

程序通过发布元数据的 `release-id` 和本地安装记录判断新版。只有远程编号大于本地编号时才进入更新流程，展示用版本号保存在 `installed.json`。启用配置后，作者还应为当前发行版本生成初始安装记录，随整合包分发。 [打包流程](packaging.md)

`enable: false` 会跳过新的更新检查。如果上次安装中断并留下 `ModpackUpdate/transaction.json`，程序仍优先恢复该事务，以便下次启动获得一致的文件状态。

## 静默更新与冲突选择

| 情况 | `silent-update: false` | `silent-update: true` |
| --- | --- | --- |
| 没有新版或检查时离线 | 继续启动游戏 | 继续启动游戏 |
| 发现新版 | 显示版本与公告，由玩家选择更新或跳过 | 自动接受更新 |
| 接受更新且没有冲突 | 游戏退出后显示安装确认窗口 | 游戏退出后直接安装 |
| 本地文件冲突、待选择的可选文件 | 显示勾选列表 | 显示勾选列表 |
| 更新完成 | 显示结果，玩家从启动器重新启动 | 显示结果，玩家从启动器重新启动 |

静默模式仍会显示下载、安装进度和结果。冲突项默认不勾选，玩家可以逐项选择、全选或全不选。勾选表示允许采用该条目的新版操作，包括覆盖文件或禁用旧模组。全不选会保留所有冲突项，其余无需选择的变更继续安装。

保护路径在生成安装计划时就已跳过，因此不会出现在冲突列表中。取消初次版本提示会继续当前游戏。取消独立程序中的安装确认时，游戏已经退出，需要从启动器重新启动。

安装完成后，即使玩家保留了部分差异，本地版本号仍会更新到已处理的目标版本，保留状态同时写入文件记录。后续发布再次改动相关路径时，会按保存的基线重新判断冲突。

## 备份和直接删除选项

默认 `delete-replaced-mods: false` 时，被同路径新版 JAR 覆盖的旧模组会移到下方目录。版本号取本次更新前的已安装版本，更新编号由程序生成。

```text
<游戏根目录>/ModpackUpdate/<旧版本号>/<更新编号>/mods/<原文件名>.jar
```

被覆盖的其他文件也按原相对路径备份，例如 `config/example.json` 会放到该版本备份目录下的 `config/example.json`。

启用 `delete-replaced-mods` 后，程序在安装期间保留用于失败恢复的旧文件，待全部文件安装成功且新版本记录提交后，清理本次被覆盖的旧 JAR 备份。配置文件等其他文件的备份仍保留。

安装确认窗口中的“直接删除被替换的旧模组，不保留备份”复选框，以 `delete-replaced-mods` 的配置值作为初始状态。在窗口修改只影响本次安装，持久修改需要编辑 `config.json`。

旧模组在新版清单中消失时，客户端将它改名为 `.jar.disable`。这个行为也适用于升级后 JAR 文件名改变时的旧文件，`delete-replaced-mods` 选项对这些禁用文件无影响。已有同名 `.disable` 时，程序使用带更新编号的禁用文件名。

## 保护路径

`protected-paths` 的每个条目都相对于游戏实例根目录，使用 `/` 分隔路径。

| 写法 | 匹配规则 |
| --- | --- |
| `options.txt` | 精确匹配根目录中的该文件 |
| `config/example-client.json` | 精确匹配指定的模组配置文件 |
| `config/example/` | 匹配该目录下的所有文件及子目录内容 |
| `saves/` | 匹配存档目录中的所有文件 |

匹配忽略大小写。目录条目以 `/` 结尾，文件条目使用完整相对路径。当前采用字符串精确匹配或目录前缀匹配，填写具体文件或目录即可，`*`、`**` 和正则表达式没有通配含义。

默认列表保护原版键位与视频设置所在的 `options.txt`、`optionsof.txt`、服务器列表 `servers.dat`、存档和截图。模组单独保存的键位或画面设置需要按其实际文件位置补充。

自定义数组会整体替换默认列表。添加自己的规则时，可保留默认条目后继续追加，例如下面的字段示例。

```json
{
  "protected-paths": [
    "options.txt",
    "optionsof.txt",
    "servers.dat",
    "saves/",
    "screenshots/",
    "config/example-client.json",
    "config/example/"
  ]
}
```

上面的示例只展示保护字段，合并到已有配置时保留更新地址、包标识等字段。`protected-paths: []` 会清空用户设置的保护列表。即使清空列表，`ModpackUpdate/` 仍由客户端保留，更新安装会跳过发布内容中的该目录。

保护规则同时跳过覆盖、新增和旧模组禁用。即使某个保护文件尚不存在，更新也会跳过对该路径的首次创建。

## 网络超时

`timeout-seconds` 的有效范围为 2–120 秒。低于 2 的值按 2 秒处理，高于 120 的值按 120 秒处理。

连接和单次 HTTP 请求使用该值。发布元数据及不超过 16 MiB 的文件响应体也使用该秒数限制读取时间。声明大小超过 16 MiB 的文件响应体最多允许读取 30 分钟。每次重定向或备用下载地址尝试会重新发起请求，因此这个选项表示单次网络阶段的限制。

启动检查只获取发布元数据。接受更新并退出游戏后，独立程序才下载整合包索引及需要安装的内容。已经完整下载且校验通过的缓存会复用。

## installed.json

该文件保存当前版本与受管文件的原始内容基线，供后续更新判断玩家是否修改过文件。作者为初始发行版本生成它，成功安装后由客户端自动维护。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema-version` | 整数 | 安装记录格式，当前为 `1` |
| `pack-id` | 字符串 | 整合包标识 |
| `release-id` | 整数 | 最近成功处理的发布编号 |
| `version` | 字符串 | 最近成功处理的展示版本 |
| `transaction-id` | 字符串 | 最近成功提交的安装事务编号，初始记录可为空字符串 |
| `files` | 对象 | 以游戏根目录相对路径为键的受管文件记录 |

`files` 中每个条目包含以下字段。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `sha512` | 字符串或 `null` | 最后采用的作者原始内容哈希，缺少可信旧基线时可为空 |
| `target-sha512` | 字符串 | 最近处理的目标内容哈希 |
| `retained` | 布尔值 | 对目标文件是否保留了本地差异或跳过了安装 |
| `optional` | 布尔值 | 最近处理版本中该文件的客户端可选属性 |

哈希字符串使用 128 位小写十六进制。作者原始哈希由已发行版本的文件内容计算，可以通过独立程序的 `seed` 命令生成。玩家修改后的磁盘文件无法提供可靠的旧原版基线。 [基线格式](publishing-protocol.md) · [初始打包流程](packaging.md)

`installed.json` 缺失时，程序以 `release-id: -1`、`version: "uninitialized"` 和空文件表处理当前实例。现有文件与新版内容一致时直接采用，内容不同时进入缺少基线的冲突选择。旧的清单外模组缺乏受管记录，会被保留。

保留 `installed.json` 能让客户端持续识别原受管文件、旧版本与玩家差异。版本字段和事务编号参与更新判断与中断恢复，应交由生成工具及客户端维护。

## 常见问题

| 现象 | 检查位置或处理方式 |
| --- | --- |
| 启动后没有检查新版 | 核对 `enable`、URL、`pack-id`，并查看远程 `release-id` 是否高于本地值 |
| 配置错误后游戏仍正常启动 | 查看 `ModpackUpdate/runtime/check-*.log`，确认 JSON 格式和字段类型 |
| 开启静默仍出现选择框 | 查看列表中是否有本地冲突、可选文件或可选改为必需的文件 |
| 全选后某个设置仍被保留 | 检查 `protected-paths` 中是否包含该文件或上级目录 |
| 开启删除选项后仍有 `.disable` 文件 | `.disable` 用于禁用清单中消失的旧模组，覆盖备份按单独规则清理 |
| 关闭更新后仍进入恢复窗口 | 查看是否存在上次安装留下的事务记录，完成恢复后再重新启动 |
| 发现新版，游戏退出后提示版本不匹配 | 核对索引声明的 Minecraft、加载器类型和版本是否与实例完全一致，NeoForge 对应 `dependencies.neoforge` |

首次发行时将 `config.json` 和生成的 `installed.json` 放进 `.mrpack` 的 `overrides/ModpackUpdate/config/`。已有实例的这两个文件由本地管理，后续发布中的同名配置会被保留目录规则跳过。 [打包流程](packaging.md)
